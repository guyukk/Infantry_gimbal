# Pitch DM-J4310 上电使能重试（2026-11-03）

> 后续实机反馈为“约 2 秒后绿灯但无输出”；本阶段的反馈门控已在 [Pitch 绿灯无输出修正](Pitch绿灯无输出修正-2026-11-03.md) 中撤销。以下保留为该阶段历史记录。

## 现象与代码依据

- 电机上电短暂变绿，随后红灯常亮；仅复位云台板后能够使能。这与云台板首次使能帧早于电机启动完成相符，但尚未通过实体 CAN 抓包确认。
- `main.c` 先打开电源，再初始化 FDCAN2；`gimbal_task` 延时 200 tick，`gimbal_init` 再延时 100 tick，然后原代码只发送一次 `Motor_enable`。若电机此时尚未接收指令，之后没有补发。
- 本工程目前把 Pitch 的命令 CAN ID 定义为 `DM_M3_ID = 0x53`，反馈按同一 `0x53` 路由至 `DM_MOTOR_MEASURE[2]`，位置命令采用 EMIT（ID `0x353`）。代码不能证明电机实际烧录的 CAN ID、Master ID 或位置范围。

## 本阶段修改

- 保留原位置的首次使能调用。若无首次发送之后的新鲜 `state == 1` 反馈，在 2000 ms 后第一次重试，随后每 500 ms 重试，总发送次数上限为 8 次。
- `Motor_enable` 返回 HAL 发送队列调用的状态。状态 0 只表示入队成功，不能证明电机已收到或已使能。
- 以新的已使能反馈确认 Pitch 可用；确认前不发送 DM EMIT 位置帧。Yaw 和拨弹电机发送路径保持原样。
- 增加 `pitch_dm_enable_status` 供 Keil Watch 查看：`attempts`、`last_tx_status`、`confirmed`、`exhausted`、`last_attempt_tick`、`confirmed_feedback_tick`。

## 目标板观察

上电后监视 `pitch_dm_enable_status`、`DM_MOTOR_MEASURE[2].fdb.state`、`DM_MOTOR_MEASURE[2].fdb.last_fdb_time`、`RxHeader2.Identifier` 和 `hfdcan2.ErrorCode`。如果 `attempts` 增至 8 且 `confirmed` 仍为 0，检查实际电机 CAN ID/Master ID、FDCAN2 收发及电机故障。若 `last_tx_status != 0`，先排查发送队列或 CAN 状态。若 `confirmed == 1`，仍须在支架安全约束下核实位置反馈与目标角度，避免 EMIT 错误位置目标驱动机构。
