# Pitch 电机绿灯但无输出：修正反馈门控（2026-11-03）

## 现象和原因

用户在上一阶段固件上观察到：上电先绿转红，约 2 秒后变绿，但 Pitch 不再输出。约 2 秒后变绿与上一阶段延迟补发使能的时序吻合；仅凭指示灯不能确认控制帧或反馈帧。

上一阶段在 `gimbal_send_cmd` 加了 `pitch_dm_enable_ready()` 门控。它必须见到首次使能之后的 `DM_MOTOR_MEASURE[2].fdb.state == 1`，才发送 EMIT 帧。当前 CAN 接收回调只把反馈 ID `0x51`～`0x58` 映射到 DM 测量数组，Pitch 索引 2 对应 `0x53`。达妙手册说明反馈帧 ID（Master ID）由调试助手独立设置，默认 0；工程中没有电机实机 Master ID 记录。因此电机即使已绿灯，若反馈 ID 不是 `0x53`、反馈未到达，或状态未更新，这一新门控也会永久挡住 EMIT 控制帧。这是本阶段可以从代码直接确认的输出回归路径；实际反馈 ID 仍需上板确认。

## 修改

- 保留原位置的首次使能和约 2 秒后开始的有限重试。`pitch_dm_enable_ready()` 继续记录新反馈与重试状态，但不再决定能否发送 EMIT。
- 恢复原来的 EMIT 发送条件：云台任务运行、`debug == 0`、三路相关电机未同时掉线、遥控器未掉线。保留原有 Yaw/拨弹与故障输出行为。
- `CAN_cmd_EMIT` 返回 FDCAN HAL 入队状态，并在 `pitch_dm_enable_status` 里记录 `emit_send_count`、`last_emit_tick`、`last_emit_tx_status`。`last_emit_tx_status` 初始为 `0xFF` 表示尚未调用；`0` 表示 HAL 入队成功，不等于电机已经执行。

## 上板调试判读

1. 观察 `pitch_dm_enable_status.emit_send_count` 是否持续增加。若不增加，检查 `debug`、`toe_is_error(DBUS_TOE)`、三路电机掉线条件及云台任务是否运行。
2. 若持续增加，查看 `last_emit_tx_status`。非 0 为 FDCAN HAL 入队失败；0 只证明进入发送队列，仍需抓包确认 `0x353` 控制帧到达电机。
3. 若 `0x353` 已到达而没有输出，核对实机 CAN ID、工作模式、EMIT 目标、机械限位及达妙调试助手的参数。当前 RAW 目标为约 `-2.25 rad`，速度上限 `30 rad/s`、电流限幅 `0.8`，应在机构安全约束下测试。
4. `pitch_dm_enable_status.confirmed == 0` 或 `exhausted == 1` 只表明当前软件没有匹配到新鲜 `0x53` 已使能反馈，不能单独判定绿灯电机失能。核对实机 Master ID；`DM_MOTOR_MEASURE[2].param.P_MIN/P_MAX` 仍未初始化，位置反馈换算也不能直接作为有效角度。
