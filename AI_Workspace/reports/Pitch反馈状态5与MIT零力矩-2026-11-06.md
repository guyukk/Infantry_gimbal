# Pitch 反馈状态 5 与 MIT 零力矩（2026-11-06）

## 设备证据

- 用户确认电机重新上电后仍为 MIT 模式，指示灯绿灯常亮。
- 云台板 Watch：`DM_MOTOR_MEASURE[2].fdb.state=5`、`fdb.id=3`、`fdb.pos=-2.77466202 rad`，`last_fdb_time` 递增；`mit_target_valid=0`、`mit_target_pos=0`、`set.KP=0`、`last_mit_tx_status=0`。
- `g_Can2RxData[0]` 是所有 FDCAN2 接收帧复用的缓存，Watch 中单独看到的 `15` 不能确定属于 Pitch 反馈。已经保存的 `fdb.state=5/id=3` 来自同一次 Pitch 反馈解析，对应原始首字节 `0x53`。

## 原因

- 旧门限只接受 `fdb.state==1`，所以新鲜反馈也被判为不可控；发送路径每周期把 `POS/KP/KD` 清零，`VEL/TOR` 也为零。`last_mit_tx_status=0` 只表示 HAL 发送入队，无法证明帧中有力矩命令。
- 这台电机 CAN ID 和 Master ID 均为 `0x53`。达妙 J4310 手册把反馈首字节写作 `ID | (ERR << 4)`。若 ID 的高四位仍出现在该字节中，正常使能码 `1` 与 ID `0x53` 按位或后仍为 `0x53`；因此高四位解析为 `5`。这与当前原始反馈和绿灯一致，但首字节已不能单独区分使能与失能。
- 参考达妙 DM-J4310-2EC V1.1 使用说明书：<https://damiao.enactic.ai/assets/files/dm-j4310-2ec-v1.1-zh-5d089e0b013d8e2fc203c5b670008a66.pdf>，反馈帧、故障码和指示灯章节。

## 源码修正

- `User/gimbal/yaw_pitch_direct.c`：MIT 发送门限额外接受当前设备已经观察到的 `CAN ID=0x53`、反馈 `state=5/id=3` 组合。反馈新鲜度、目标有效性门限保留；其他 ID、状态 `8` 等故障反馈仍发零刚度。
- `pitch_dm_enable_ready` 没有把 `state=5` 当作可证实的使能状态，仍按原有次数重试。由于 ID/状态位重叠，`confirmed=0` 或最终 `exhausted=1` 在此配置下不能单独证明电机未使能。
- 这属于现有电机 ID 配置下的兼容处理。较清晰的长期方案是将电机接收 CAN ID 配为不占用状态高四位的低 ID，例如 `0x03`，Master ID 保持唯一的 `0x53`，并同步修改本工程发送 ID；应作为设备配置与固件同步变更执行。
