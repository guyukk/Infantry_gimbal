## 3. 第一步：持续检测、非法输入和最终输出保护

### 3.1 健康数据与恢复规则

两板分别持有本地 health.c/h，无运行时跨仓库依赖。短 PRIMASK 临界区发布/读取 last_valid_ms、generation、seen、valid、fault_generation；查询还提供 age_ms、fresh、reason。时间戳 0 是合法接收时间，不再被当成“从未收到”。无等待、堆分配或新健康任务。

所有本阶段输入采用新增 100ms 保护阈值：age <=100ms 新鲜，101ms 失效。这个值是本次保护策略，不能写成实测设备周期。RC、板间状态和电机只在真实、通过验证的接收事件续期；IMU 只在真实有效样本/解算完成后续期，任务持续运行不等于数据有效。

失效时最终发送函数再次检查依赖，不能仅靠上游状态机的零值。恢复必须所有依赖重新新鲜，并出现故障之后的新合法 RC；不是要求松杆到中位，也不是要求额外解锁手势。故障记录 epoch 驱动 PID/目标/射击历史清理。接收恢复若距上帧已超过100ms，即使两次控制轮询都没看到离线，也记录 fault_generation / 门跳变，防止掩盖失联。非法帧后立即正常帧也保留故障代数，让自瞄和主机清理旧请求。

复核还重现调用者先取 now、随后 IRQ 发布更晚时间戳时的无符号减法误超时。最终 source_age 只有在 HAL 当前时钟确认新时间已发生时才追平读取时间，兼顾正常计时和 uint32 回绕；保留失败1030→通过的回归。

### 3.2 底盘 C

- remote_control.c 先解包到局部候选，检查 ch0..3 在 ±700、开关1..3，通过后在临界区发布 rc_ctrl 和健康元数据。非法/短帧保持上一份 rc_ctrl 原始字节，立即使 RC 健康失效；RC_data_is_error 只查询，不能再修补/伪造遥控输入。任务使用 remote_control_snapshot 一致副本。
- 46B 板间帧通过现有 B02 完整性/字段验证后才续期 BOARD。底盘实际使用云台 yaw，因此 BOARD 是底盘控制的必要依赖。
- CAN 接收要求 HAL 成功、标准数据帧、DLC8、正确总线；201..204 只收 CAN1，205..208 只收 CAN2，编码器值小于8192。每个电机独立记录，不再把“曾收到一次”当持续在线。
- GYRO、ACCEL 由实际 DMA 解码有效数值更新；INS 有限角度且两种样本都新鲜时更新 IMU。chassis_motor_feedback_ready 以8路健康为准。
- 底盘总门依赖 RC + BOARD + IMU + 8个电机；任一失效，CAN_cmd_CHAS3508 和 CAN_cmd_CHAS6020 的8路最终电流归零，PID及软转向目标历史清理。恢复后从当前反馈重建状态。
- 原 motor_feedback_seen 的写入残留不再有在线判定权威，后续可在死代码清理批次移除，本次不以此宣称全面清理完成。

### 3.4 IMU 阻塞与有效样本

云台 INS 任务优先级高于云台控制任务。BMI088 原单次SPI超时1000ms会使故障期间的健康门失去及时运行机会，因此单次上限改为1ms，批内首次SPI失败后停止后续传输；有效批状态与芯片ID共同决定 sample_valid。失败批不推进 IMU 健康，也不继续用无效值解算；接收字节先初始化，避免使用未定义值。

正常1ms任务周期与控制参数未改；加了芯片ID有效性检查。没有处理温控方向/残余PWM，没有改变加热器极性；这些属于 B04/P06。1ms HAL超时和跳过批次的离线通过不等于实测调度延迟已达标。

## 4. 第二步：自瞄与主机仲裁

### 4.1 自瞄

- AUTO_AIM_TIMEOUT=2000ms 在 debug=0 与 release=1 都有效，以 MCU 本地有效 DELTA 到达时间计算；2000ms仍有效，2001ms退出。host时间戳和status保留为不透明元数据，不作为新鲜度证明；last_fdb只在真实接收更新。
- OFF、超时、本地不允许或所需健康故障，清误差控制历史、D项、速度、滤波和待消费角增量，设置接收代数门槛。接收邮箱可保留最后一帧用于诊断，但旧代数不可再驱动控制。
- R 边沿开关自瞄；重新开启必须再收到新 DELTA，OFF期间缓存的视觉数据不会复活。有效零误差参与中值滤波，去掉“零值继续保持旧非零值”的行为。
- 角度消费者通过 auto_aim_take_increment 原子读取并清除单轴增量；INIT时也通过该接口丢弃待消费值。保留原误差→有限速度→每周期角增量控制语义、增益和限幅。
- uproto_tick 仅由 COMM_APP 驱动，移除自瞄任务重复推进协议状态的路径。短临界区保证发布/清理与消费不会相互覆盖；实际IRQ延迟仍需硬件测量。

### 4.2 主机命令

comm_app.c 不再把 const RC 指针强转为可写，不再注入鼠标/键盘/开关。新增独立 host_control 邮箱，由真实通信回调提交，本地 shoot 状态机消费。

| 条件 | 决策 |
| --- | --- |
| 本地停止/云台不允许、E关闭摩擦轮、手动鼠标/拨杆射击 | 本地优先，取消主机请求 |
| 未到 SHOOT_READY_BULLET，包括摩擦轮预热期 | 拒绝主机启动 |
| 自瞄不就绪或所需健康失效 | 拒绝/取消，恢复不重放旧请求 |
| 主机连续射击超过120ms无新请求 | 退出主机连发，回 READY_BULLET；不伪造RC释放沿 |
| 主机单发 | 在20ms消费窗口内只取一次；非零token与最近token去重，零token按0→1沿触发 |
| 主机底盘速度SID | 仍可解析，明确不执行，只增加 unsupported 计数 |

非零token只保存“最近一次”历史，并跨取消/超时保留；不是无限历史去重，也不是全序列防重放。零token需要实际off后再on，不因超时合成新上升沿。pending单发过期不会迟到补发。主机接收时捕获故障上下文，即使故障与恢复发生在两次邮箱轮询之间，原请求也取消。

host_control_get_stats 提供 accepted/rejected/duplicates/expired/chassis_unsupported。accepted表示通过本地输入校验，不表示真实打出一发；没有更改协议字段或凭空承诺执行成功应答。
