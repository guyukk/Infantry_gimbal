# B06 维护边界、参数与观察入口

日期：2026-11-16，证据批次20261116-210254。数值以当前 Target 宏和实际调用为准；不能用旧文档覆盖现车零位。当前模块拆分未修复小陀螺平移问题。

## 模块职责及共享状态

| 模块 | 责任及写入者 | 边界 |
| --- | --- | --- |
| C `chassis_task.c` | chassis任务：输入快照、状态/最终输出组织 | 只调用软转向纯计算，不增加通信/Flash职责 |
| C `chassis_soft_turn.c` | 纯目标整形，由chassis任务独占状态 | 算法及参数本批不变 |
| G `yaw_pitch_direct.c` | gimbal任务：Yaw与两轴控制流程 | 轴健康恢复与PID历史仍集中复位 |
| G `pitch_dm_control.c` | gimbal任务：DM使能、反馈状态判定、MIT限位/向内恢复 | 原函数体逐项迁移，保留零刚度保护与0.02rad例外 |
| G `pitch_calibration.c` | cali任务：两点采样、独立Pitch记录、CRC/回读/重试 | Flash在临界区外；记录/当前限位共同应用时保留原短临界区 |
| G `calibrate_task.c` | cali任务：HD/GM旧扇区及操作调度 | 调用Pitch模块，不把存储布局混入控制算法 |
| G `host_control.c` | 主机独立请求、超时、重复token及本地优先仲裁 | B03已有边界保留；comm_app只作通道适配 |
| G `gimbal_channel.c` | COMM_APP的有界协议消费路径发布DELTA | 直接进入auto_aim的一致性发布；移除无人读取的第二邮箱 |
| 两端 `health.c` | ISR/有效样本发布，任务/最终输出读取 | 短PRIMASK快照；保持100ms门限和新RC恢复 |

DM反馈仅由CAN接收更新；Pitch使能/MIT历史主要由gimbal任务更新，校准应用在既有短临界区重置目标有效性。初始化写入顺序保留。`volatile`不是跨任务一致性的替代，不能绕过现有快照/临界区直接组合多个字段。

## 编码、命名和时序观察

GBK文件先按GBK严格解码，再转UTF-8，原始字节在B06-before包。此次转换包含C的bsp_rc.c、bsp_usart.c/h、remote_control.h；已是UTF-8的文件不作有损解码。去注释后的函数体对照确认没有可执行字符串或业务表达式漂移。未尝试批量修复全仓已有的二次乱码。

公开线上结构、PID字段、emit_pos_set等兼容名称不做大规模重命名。唯一主动Watch迁移为B04的共享摩擦轮PID→`fric1.speed_pid`/`fric2.speed_pid`；Pitch使能/校准状态变量名保持，所属源文件改变。

两端新增 `control_loop_diag`：iterations、last/max_period_ms、late_starts、last/max_execution_ms、execution_overruns。控制任务单写，不打印、不分配内存，不改优先级或delay方式。计数按HAL毫秒时间，0ms不等于零耗时；不能据此验证亚毫秒WCET。G执行段在vTaskDelay前结束，不含延时后的原栈余量查询。

栈观察沿用C `chassis_high_water`、G `gimbal_high_water`；堆在Symbols定位heap_4.c的 `xFreeBytesRemaining`/`xMinimumEverFreeBytesRemaining`（字节）。CAN入队失败和RX错误使用health.c中的buses；HAL入队成功不代表ACK或电机动作。任务级读取组合状态须短临界区复制；Keil Watch可用于定位，不能冒充原子遥测。

真实执行耗时、调度抖动、栈/堆低水位和设备负载均为 **not_measured**。验证方法：同一固件确认正常任务和满通信负载下计数是否递增/出现超期，再用DWT或示波器测亚毫秒控制段；测量工具需单独评审，不默认开启裁判串口高频日志。
