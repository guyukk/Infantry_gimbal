# B05 UI与接口有效性

2026-11-15最终实现，字段布局/SID不变；见[B05报告](B05-实施与软件签收报告.md)。

## C显示

UI从gimbal_status_snapshot取得同一帧的状态，要求seen、46B年龄<=100ms及HEALTH_BOARD有效；不会拿旧chassis_move状态当持续在线。

| 项目 | 有效映射 | 缺失/过期/非法 |
| --- | --- | --- |
| 本地底盘 | 0 STOP，1 C_YAW，2 SPIN | UNK，负枚举也不越界 |
| 云台线上行为 | 0 FREE，1 INIT，2 CALI，3 ABS，4 REL，5 SPIN，6 HOLD | UNK |
| 射击线上模式 | 0 OFF，1 WARM，2 RDY，3 SING，4 CONT | UNK |
| 自瞄 | 46B无该字段 | 始终UNK，不假装OFF |
| 血量 | 实际且正确长度的0x0201状态包，<=1000ms | HP:??，数值0仅作不可用占位 |
| 超电百分比 | 标准PM01 0x612数据响应、DLC>=6，<=1000ms，20..26V线性估计 | UNK，不伪装0% |

字符串容量30B，状态宽5、自瞄3且有容量断言。PM01百分比不是验证过的SOC，也不是功率控制；没有启动旧轮询/限功率算法。其他裁判包不续期血量，PM其他对象不续期电压。C原接收流负责CRC前置；新增快照不是新协议解码器。UI刷新还要求RC指针存在且健康新鲜。robot_id可作客户端路由参考，不证明血量新鲜。

## G主机接口

- gimbal_get_state要求Yaw/Pitch/IMU均新鲜，所有弧度→int32微度转换有限且不溢出；缺数据返回false，不把0冒充测量。
- 当前没有完整热量/弹量/许可源，裁判发布保持NOT_READY|TIMEOUT、fire_allowed=0，不因本地全局变量残留置VALID。新鲜28B的1..7/101..107身份可作robot_id和敌方阵营参考；过期/非法身份为0并置ERROR，game_stage为不可用占位0。
- 主机底盘命令仍可识别但不支持，射击沿用B03独立邮箱、本地优先/120ms超时/20ms单发，不改RC、不新增执行成功应答。
- C→G的vx/vy/wz继续兼容占位。C无实际整车速度正解算赋值，0不能证明静止，不能把目标伪装实际；G仅存储/字段校验，无活动控制消费者拿它判断静止。本轮不新增里程计。
- G→C yaw仍为原编码角换算，不改成校准相对角；28/46B、VTM21B及19B+7B均保持golden/历史合法帧兼容。

新鲜、数值合法、控制获准、机械动作完成是不同条件；本批显示/状态不是射击或实机校准完成证明。
